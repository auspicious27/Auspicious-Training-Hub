Hour 1: Relational Model

What is Relational Model?

The relational model organizes data into tables (relations). Each table has rows (tuples) and columns (attributes).

Student Table Example:

┌────────────┬──────────┬─────┬────────────┐
│ Student_ID │   Name   │ Age │    City    │
├────────────┼──────────┼─────┼────────────┤
│    101     │  John    │  20 │  New York  │
│    102     │  Alice   │  21 │  London    │
│    103     │  Bob     │  22 │  Paris     │
└────────────┴──────────┴─────┴────────────┘

Table (Relation)
Rows (Tuples/Records)
Columns (Attributes/Fields)

Relational Model Terminology:

  • Relation: Table
  • Tuple: Row/Record
  • Attribute: Column/Field
  • Domain: Set of allowed values for attribute
  • Degree: Number of columns
  • Cardinality: Number of rows

Relational Schema

A schema defines the structure of a table.

Schema Notation:

Student(Student_ID, Name, Age, City)
        ↑          ↑
   Table Name  Attributes

Course(Course_ID, Course_Name, Credits)

Enrollment(Student_ID, Course_ID, Grade)
           ↑           ↑
      Foreign Keys

Relationships Between Tables

Tables are connected using foreign keys.

Example: Student-Course Relationship:

Student Table:
┌────────────┬──────────┐
│ Student_ID │   Name   │
├────────────┼──────────┤
│    101     │  John    │
│    102     │  Alice   │
└────────────┴──────────┘

Course Table:
┌───────────┬──────────────┐
│ Course_ID │ Course_Name  │
├───────────┼──────────────┤
│   CS101   │     DSA      │
│   CS102   │    DBMS      │
└───────────┴──────────────┘

Enrollment Table (Junction):
┌────────────┬───────────┬───────┐
│ Student_ID │ Course_ID │ Grade │
├────────────┼───────────┼───────┤
│    101     │   CS101   │   A   │
│    101     │   CS102   │   B   │
│    102     │   CS101   │   A   │
└────────────┴───────────┴───────┘

Integrity Constraints

Constraints are rules that ensure data accuracy and consistency.

NOT NULL

Column cannot have NULL value.

Student_ID NOT NULL
Name NOT NULL

✓ Valid: 101, "John"
✗ Invalid: NULL, "John"

UNIQUE

All values must be different.

Email UNIQUE

✓ Valid: Different emails
✗ Invalid: Duplicate email

PRIMARY KEY

NOT NULL + UNIQUE. Identifies record.

Student_ID PRIMARY KEY

✓ Unique, not null
✗ Duplicate or NULL

FOREIGN KEY

References primary key of another table.

Student_ID FOREIGN KEY
REFERENCES Student

✓ Must exist in Student
✗ Invalid Student_ID

Additional Constraints:

  • CHECK: Validates condition (e.g., Age > 0)
  • DEFAULT: Sets default value if none provided
Age INT CHECK (Age >= 18)
Status VARCHAR DEFAULT 'Active'

Referential Integrity

Referential integrity ensures foreign key values exist in referenced table.

Example:

Enrollment Table:
Student_ID (FK) → Must exist in Student table

✓ Valid: Student_ID = 101 (exists in Student)
✗ Invalid: Student_ID = 999 (doesn't exist)

Referential Actions:

  • CASCADE: Delete/update related records
  • SET NULL: Set foreign key to NULL
  • RESTRICT: Prevent deletion if references exist

Hour 2: Normalization

What is Normalization?

Normalization is the process of organizing data to reduce redundancy and improve data integrity.

Why Normalization?

  • Eliminate data redundancy
  • Prevent data anomalies
  • Ensure data consistency
  • Improve database design
  • Easier maintenance

Data Redundancy Problems

Unnormalized Table:

┌────────────┬──────────┬────────────┬──────────────┐
│ Student_ID │   Name   │   Course   │ Instructor   │
├────────────┼──────────┼────────────┼──────────────┤
│    101     │  John    │    DSA     │  Dr. Smith   │
│    101     │  John    │    DBMS    │  Dr. Jones   │
│    102     │  Alice   │    DSA     │  Dr. Smith   │
└────────────┴──────────┴────────────┴──────────────┘

Problems:
1. John's name repeated (redundancy)
2. If John changes name, update multiple rows
3. If DSA instructor changes, update multiple rows

Data Anomalies

Insertion Anomaly

Cannot insert data without other data.

Problem: Can't add new course
without student enrollment

Deletion Anomaly

Deleting data loses other information.

Problem: Delete last student
loses course information

Update Anomaly

Updating requires multiple changes.

Problem: Change instructor
requires updating all rows

Normal Forms

First Normal Form (1NF)

Each column contains atomic (indivisible) values. No repeating groups.

Not in 1NF:

┌────────────┬──────────┬─────────────────┐
│ Student_ID │   Name   │     Courses     │
├────────────┼──────────┼─────────────────┤
│    101     │  John    │  DSA, DBMS, OS  │ ← Multiple values
└────────────┴──────────┴─────────────────┘

In 1NF:

┌────────────┬──────────┬────────────┐
│ Student_ID │   Name   │   Course   │
├────────────┼──────────┼────────────┤
│    101     │  John    │    DSA     │
│    101     │  John    │    DBMS    │
│    101     │  John    │     OS     │
└────────────┴──────────┴────────────┘

1NF Rules:

  • Each column has atomic values
  • No repeating groups
  • Each row is unique

Second Normal Form (2NF)

Must be in 1NF. No partial dependency (non-key attributes depend on entire primary key).

Not in 2NF:

Enrollment(Student_ID, Course_ID, Student_Name, Grade)
           Primary Key: (Student_ID, Course_ID)

Problem: Student_Name depends only on Student_ID
         (partial dependency)

In 2NF:

Student(Student_ID, Student_Name)
Enrollment(Student_ID, Course_ID, Grade)

Now: All non-key attributes depend on entire key

Third Normal Form (3NF)

Must be in 2NF. No transitive dependency (non-key attributes depend only on primary key).

Not in 3NF:

Student(Student_ID, Name, Dept_ID, Dept_Name)

Problem: Dept_Name depends on Dept_ID
         (transitive dependency)

In 3NF:

Student(Student_ID, Name, Dept_ID)
Department(Dept_ID, Dept_Name)

Now: No transitive dependencies

Normalization Benefits:

  • Reduced redundancy: Data stored once
  • Data consistency: Single source of truth
  • Easier updates: Change in one place
  • Better integrity: Fewer anomalies
  • Flexible design: Easy to modify

⚠️ Denormalization

Sometimes we intentionally add redundancy for performance (faster queries). This is called denormalization.

Use when: Read performance is critical and data doesn't change often.

Assessment

Test your understanding of relational model and normalization:

Question 1: Relational Model

What is a tuple in relational model?

Answer: A row/record in a table

Explanation: Tuple represents a single record with all its attributes.

Question 2: Primary Key Constraint

Can primary key have NULL values?

Answer: No

Explanation: Primary key must be NOT NULL and UNIQUE.

Question 3: Foreign Key

What does foreign key ensure?

Answer: Referential integrity

Explanation: Foreign key values must exist in referenced table.

Question 4: Normalization Purpose

Why do we normalize databases?

Answer: Reduce redundancy and anomalies

Explanation: Normalization eliminates data duplication and inconsistencies.

Question 5: 1NF Rule

What does 1NF require?

Answer: Atomic values in each column

Explanation: No multi-valued or composite attributes allowed.

Question 6: Update Anomaly

What is an update anomaly?

Answer: Need to update multiple rows for one change

Explanation: Caused by data redundancy.

Question 7: 2NF Requirement

What must be eliminated for 2NF?

Answer: Partial dependencies

Explanation: All non-key attributes must depend on entire primary key.

Question 8: 3NF Requirement

What must be eliminated for 3NF?

Answer: Transitive dependencies

Explanation: Non-key attributes should depend only on primary key.

Question 9: CHECK Constraint

What does CHECK constraint do?

Answer: Validates a condition

Explanation: Ensures values meet specified criteria (e.g., Age > 0).

Question 10: Denormalization

When is denormalization used?

Answer: For better read performance

Explanation: Intentionally add redundancy to speed up queries.

Key Takeaways

  • Relational model organizes data in tables
  • Tables have rows (tuples) and columns (attributes)
  • Constraints ensure data integrity
  • Primary key is NOT NULL and UNIQUE
  • Foreign key creates relationships between tables
  • Normalization reduces redundancy
  • 1NF: Atomic values, no repeating groups
  • 2NF: No partial dependencies
  • 3NF: No transitive dependencies
  • Normalization prevents insertion, deletion, update anomalies
