Hour 1: DBMS Basics

What is Data, Database, and DBMS?

Definitions:

  • Data: Raw facts and figures (e.g., "John", 25, "New York")
  • Information: Processed data with meaning (e.g., "John is 25 years old and lives in New York")
  • Database: Organized collection of related data
  • DBMS: Software to create, manage, and access databases

Real-World Examples of Databases:

  • Banking: Customer accounts, transactions
  • E-commerce: Products, orders, customers
  • Social Media: Users, posts, comments
  • Hospital: Patients, doctors, appointments
  • University: Students, courses, grades

Popular DBMS Software:

  • MySQL: Open-source, widely used
  • PostgreSQL: Advanced open-source
  • Oracle: Enterprise-level
  • SQL Server: Microsoft's DBMS
  • MongoDB: NoSQL database

Problems with File-Based Systems

Before DBMS, data was stored in files. This approach had many problems:

File System Problems:

  • Data Redundancy: Same data stored multiple times
  • Data Inconsistency: Different copies have different values
  • Difficult Access: Need to write programs for each query
  • No Security: Anyone can access files
  • No Concurrent Access: Multiple users can't access simultaneously
  • No Backup/Recovery: Data loss is permanent

Example of Data Redundancy:

Student File:
ID: 101, Name: John, Dept: CS, Dept_Head: Dr. Smith

Course File:
Course: DSA, Dept: CS, Dept_Head: Dr. Smith

Problem: Dept_Head stored twice!
If Dr. Smith retires, need to update multiple files.

Need for DBMS

DBMS solves all file system problems and provides many advantages:

1. Data Security

  • User authentication
  • Access control
  • Encryption
  • Audit trails

2. Data Consistency

  • Single source of truth
  • No redundancy
  • Integrity constraints
  • ACID properties

3. Data Sharing

  • Multiple users
  • Concurrent access
  • Locking mechanisms
  • Transaction management

4. Backup & Recovery

  • Automatic backups
  • Point-in-time recovery
  • Crash recovery
  • Data durability

Additional DBMS Advantages:

  • Data Independence: Change storage without affecting applications
  • Reduced Development Time: Built-in functions for common tasks
  • Data Integrity: Enforce rules and constraints
  • Better Decision Making: Easy data analysis
  • Scalability: Handle growing data

Real-World DBMS Applications:

  • Banking: ATM transactions, account management
  • Airlines: Reservations, flight schedules
  • Telecom: Call records, billing
  • Education: Student records, online learning
  • Healthcare: Patient records, prescriptions

Hour 2: ER Model & Keys

What is ER Model?

The Entity-Relationship (ER) Model is a high-level conceptual data model used to design databases. It represents data as entities, attributes, and relationships.

ER Model Components:

  • Entity: Real-world object (e.g., Student, Course)
  • Attribute: Property of entity (e.g., Name, Age)
  • Relationship: Association between entities (e.g., Student enrolls in Course)

Entity

An entity is a real-world object that can be distinctly identified.

Examples of Entities:

  • Student: John, Alice, Bob
  • Course: DSA, DBMS, Python
  • Employee: E101, E102, E103
  • Product: Laptop, Phone, Tablet

Entity Types:

  • Strong Entity: Has its own key (e.g., Student with Student_ID)
  • Weak Entity: Depends on another entity (e.g., Dependent of Employee)

Attribute

An attribute is a property or characteristic of an entity.

Student Entity Attributes:

Student
├── Student_ID (Key attribute)
├── Name
├── Age
├── Email
└── Phone

Types of Attributes:

  • Simple: Cannot be divided (e.g., Age)
  • Composite: Can be divided (e.g., Name = First_Name + Last_Name)
  • Single-valued: One value (e.g., Date_of_Birth)
  • Multi-valued: Multiple values (e.g., Phone_Numbers)
  • Derived: Calculated from other attributes (e.g., Age from DOB)

Relationship

A relationship is an association between two or more entities.

Examples of Relationships:

  • Student enrolls in Course
  • Employee works in Department
  • Customer places Order
  • Doctor treats Patient

Types of Relationships:

  • One-to-One (1:1): One entity relates to one other
    Example: Person has one Passport
  • One-to-Many (1:M): One entity relates to many others
    Example: Department has many Employees
  • Many-to-Many (M:N): Many entities relate to many others
    Example: Students enroll in many Courses, Courses have many Students

ER Diagram Example:

│ Student │─────────│ Course  │
└─────────┘ Enrolls └─────────┘
    │                    │
    │                    │
 Attributes          Attributes
 - ID (PK)           - Code (PK)
 - Name              - Name
 - Age               - Credits

Database Keys

Keys are attributes that uniquely identify records in a table.

Primary Key

Uniquely identifies each record. Cannot be NULL.

Student Table:
Student_ID (PK) | Name
101             | John
102             | Alice

Foreign Key

References primary key of another table. Creates relationships.

Enrollment Table:
Student_ID (FK) | Course_ID
101             | CS101
102             | CS101

Candidate Key

Attributes that can be primary key. Minimal set that uniquely identifies.

Student:
- Student_ID ✓
- Email ✓
- Phone ✓
Any can be PK

Super Key

Any combination of attributes that uniquely identifies.

Super Keys:
- Student_ID
- Email
- (ID, Name)
- (ID, Email)

Additional Key Types:

  • Composite Key: Primary key with multiple attributes
    Example: (Student_ID, Course_ID) in Enrollment
  • Alternate Key: Candidate keys not chosen as primary key
  • Unique Key: Ensures uniqueness but can be NULL

Importance of Keys:

  • Uniqueness: Identify records uniquely
  • Relationships: Connect tables via foreign keys
  • Integrity: Maintain data accuracy
  • Indexing: Faster data retrieval
  • Constraints: Enforce business rules

Explanation: DBMS is used wherever organized data storage is needed.

Key Takeaways

  • DBMS is software to manage databases
  • File systems have redundancy and inconsistency problems
  • DBMS provides security, consistency, sharing, backup
  • ER Model is used for database design
  • Entity is a real-world object
  • Attribute is a property of entity
  • Relationship connects entities (1:1, 1:M, M:N)
  • Primary key uniquely identifies records
  • Foreign key creates table relationships
  • Keys ensure data integrity and enable relationships
