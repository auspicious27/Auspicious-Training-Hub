Hour 1: Recursion

What is Recursion?

Recursion is a technique where a function calls itself to solve a problem by breaking it into smaller subproblems.

Real-World Analogy:

Imagine Russian nesting dolls (Matryoshka):

  • Open a doll, find a smaller doll inside
  • Open that doll, find an even smaller one
  • Continue until you reach the smallest doll (base case)
  • This is recursion - solving by going deeper!

Key Components of Recursion:

  • Base Case: Stopping condition (prevents infinite recursion)
  • Recursive Case: Function calls itself with simpler input
  • Progress: Each call moves toward base case

Example 1: Simple Recursion - Countdown

def countdown(n):
    """Count down from n to 1"""
    # Base case
    if n <= 0:
        print("Done!")
        return
    
    # Recursive case
    print(n)
    countdown(n - 1)  # Call itself with smaller value

# Test
countdown(5)
Output: 
5
4
3
2
1
Done!

Example 2: Factorial Using Recursion

def factorial(n):
    """
    Calculate factorial using recursion
    factorial(5) = 5 * 4 * 3 * 2 * 1 = 120
    """
    # Base case
    if n == 0 or n == 1:
        return 1
    
    # Recursive case
    return n * factorial(n - 1)

# Test
for i in range(6):
    print(f"{i}! = {factorial(i)}")
Output: 
0! = 1
1! = 1
2! = 2
3! = 6
4! = 24
5! = 120

Call Stack Visualization (factorial(4)):

factorial(4)
  → 4 * factorial(3)
      → 3 * factorial(2)
          → 2 * factorial(1)
              → 1 (base case)
          ← returns 1
      ← returns 2 * 1 = 2
  ← returns 3 * 2 = 6
← returns 4 * 6 = 24

def fibonacci(n):
    """
    Calculate nth Fibonacci number
    Sequence: 0, 1, 1, 2, 3, 5, 8, 13, ...

    # Base cases

Example 5: Power Function

def power(base, exp):
    """Calculate base^exp using recursion"""
    # Base case
    if exp == 0:
        return 1
    
    # Recursive case
    return base * power(base, exp - 1)

# Test
print(f"2^5 = {power(2, 5)}")
print(f"3^4 = {power(3, 4)}")
print(f"5^3 = {power(5, 3)}")
Output: 
2^5 = 32
3^4 = 81
5^3 = 125

Example 6: Recursion vs Iteration

# Recursive approach
def factorial_recursive(n):
    if n <= 1:
        return 1
    return n * factorial_recursive(n - 1)

# Iterative approach
def factorial_iterative(n):
    result = 1
    for i in range(1, n + 1):
        result *= i
    return result

# Test both
n = 5
print(f"Recursive: {n}! = {factorial_recursive(n)}")
print(f"Iterative: {n}! = {factorial_iterative(n)}")

Recursion vs Iteration:

Feature Recursion Iteration
Code More elegant More verbose
Memory Uses call stack Less memory
Speed Slower (overhead) Faster
Use When Problem naturally recursive Performance critical

⚠️ Recursion Pitfalls:

  • Stack overflow: Too many recursive calls
  • Inefficiency: Repeated calculations (e.g., Fibonacci)
  • No base case: Infinite recursion

Hour 2: Advanced Sorting

Merge Sort

Merge sort uses divide-and-conquer strategy. It divides array into halves, sorts them, and merges them back.

Algorithm:

  1. Divide: Split array into two halves
  2. Conquer: Recursively sort both halves
  3. Combine: Merge sorted halves

Example 7: Merge Sort Visualization

# Merge Sort Process
"""
Initial: [38, 27, 43, 3, 9, 82, 10]

Divide:
[38, 27, 43, 3] | [9, 82, 10]
[38, 27] [43, 3] | [9, 82] [10]
[38] [27] [43] [3] | [9] [82] [10]

Merge:
[27, 38] [3, 43] | [9, 82] [10]
[3, 27, 38, 43] | [9, 10, 82]
[3, 9, 10, 27, 38, 43, 82]
"""

Example 8: Merge Sort Implementation

def merge_sort(arr):
    """
    Merge Sort Algorithm
    Time Complexity: O(n log n)
    Space Complexity: O(n)
    """
    if len(arr) <= 1:
        return arr
    
    # Divide
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    
    # Conquer (merge)
    return merge(left, right)

def merge(left, right):
    """Merge two sorted arrays"""
    result = []
    i = j = 0
    
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    
    result.extend(left[i:])
    result.extend(right[j:])
    return result

# Test
numbers = [38, 27, 43, 3, 9, 82, 10]
print(f"Original: {numbers}")
sorted_numbers = merge_sort(numbers)
print(f"Sorted: {sorted_numbers}")
Output: 
Original: [38, 27, 43, 3, 9, 82, 10]
Sorted: [3, 9, 10, 27, 38, 43, 82]

Merge Sort Characteristics:

  • Time: O(n log n) - all cases
  • Space: O(n) - needs extra space
  • Stable: Yes
  • Best for: Large datasets, linked lists

Quick Sort

Quick sort picks a pivot element and partitions array around it. Elements smaller than pivot go left, larger go right.

Algorithm:

  1. Choose pivot: Select an element as pivot
  2. Partition: Rearrange array around pivot
  3. Recursively sort: Sort left and right partitions

Example 9: Quick Sort Implementation

def quick_sort(arr):
    """
    Quick Sort Algorithm
    Time Complexity: O(n log n) average, O(n²) worst
    Space Complexity: O(log n)
    """
    if len(arr) <= 1:
        return arr
    
    # Choose pivot (last element)
    pivot = arr[-1]
    
    # Partition
    left = [x for x in arr[:-1] if x <= pivot]
    right = [x for x in arr[:-1] if x > pivot]
    
    # Recursively sort and combine
    return quick_sort(left) + [pivot] + quick_sort(right)

# Test
numbers = [64, 34, 25, 12, 22, 11, 90]
print(f"Original: {numbers}")
sorted_numbers = quick_sort(numbers)
print(f"Sorted: {sorted_numbers}")
Output: 
Original: [64, 34, 25, 12, 22, 11, 90]
Sorted: [11, 12, 22, 25, 34, 64, 90]

Assessment

Test your understanding of recursion and advanced sorting:

Question 1: Recursion Definition

What is recursion?

Answer: Function calling itself

Explanation: Recursion is when a function calls itself to solve smaller subproblems.

Question 2: Base Case

Why is base case important in recursion?

Answer: Prevents infinite recursion

Explanation: Base case is the stopping condition that ends recursion.

Question 3: Merge Sort Complexity

What is the time complexity of merge sort?

Answer: O(n log n)

Explanation: Merge sort has O(n log n) complexity in all cases.

Question 4: Quick Sort Pivot

What is the role of pivot in quick sort?

Answer: Partitioning element

Explanation: Pivot is used to partition array into smaller and larger elements.

Question 5: Recursion vs Iteration

Which uses more memory?

Answer: Recursion

Explanation: Recursion uses call stack, consuming more memory.

Question 6: Merge Sort Strategy

What strategy does merge sort use?

Answer: Divide and conquer

Explanation: Divides problem into smaller parts, solves them, and combines results.

Question 7: Factorial Base Case

What is the base case for factorial(n)?

Answer: n = 0 or n = 1

Explanation: factorial(0) = factorial(1) = 1

Question 8: Quick Sort Worst Case

When does quick sort have O(n²) complexity?

Answer: Already sorted array

Explanation: Poor pivot choice leads to unbalanced partitions.

Question 9: Merge Sort Stability

Is merge sort a stable sorting algorithm?

Answer: Yes

Explanation: Merge sort maintains relative order of equal elements.

Question 10: Recursion Advantage

What is the main advantage of recursion?

Answer: Elegant code for complex problems

Explanation: Recursion provides clean solutions for naturally recursive problems.

Key Takeaways

  • Recursion is a function calling itself
  • Every recursion needs a base case
  • Recursion uses call stack memory
  • Merge sort uses divide-and-conquer - O(n log n)
  • Quick sort uses partitioning - O(n log n) average
  • Merge sort is stable, quick sort is not
  • Merge sort needs O(n) extra space
  • Quick sort is in-place sorting
  • Both are much faster than bubble/selection sort
  • Choose algorithm based on data characteristics
