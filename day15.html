Hour 1: SQL Core Concepts

What is SQL?

SQL (Structured Query Language) is a standard language for managing and manipulating relational databases.

Why SQL is Important:

  • Universal database language
  • Easy to learn and use
  • Powerful data manipulation
  • Industry standard
  • Required for most tech jobs

Types of SQL Commands:

  • DDL (Data Definition Language): CREATE, ALTER, DROP, TRUNCATE
  • DML (Data Manipulation Language): SELECT, INSERT, UPDATE, DELETE
  • DCL (Data Control Language): GRANT, REVOKE
  • TCL (Transaction Control Language): COMMIT, ROLLBACK, SAVEPOINT

Basic SQL Commands

Example 1: SELECT Statement

Retrieve data from database.

-- Select all columns
SELECT * FROM Students;

-- Select specific columns
SELECT Name, Age FROM Students;

-- Select with condition
SELECT * FROM Students WHERE Age > 20;

-- Select with multiple conditions
SELECT * FROM Students 
WHERE Age > 20 AND City = 'New York';

-- Select with pattern matching
SELECT * FROM Students 
WHERE Name LIKE 'J%';  -- Names starting with J

Example 2: INSERT Statement

Add new records to table.

-- Insert single record
INSERT INTO Students (Student_ID, Name, Age, City)
VALUES (101, 'John', 20, 'New York');

-- Insert multiple records
INSERT INTO Students (Student_ID, Name, Age, City)
VALUES 
    (102, 'Alice', 21, 'London'),
    (103, 'Bob', 22, 'Paris'),
    (104, 'Charlie', 23, 'Tokyo');

Example 3: UPDATE Statement

Modify existing records.

-- Update single column
UPDATE Students
SET Age = 21
WHERE Student_ID = 101;

-- Update multiple columns
UPDATE Students
SET Age = 22, City = 'Boston'
WHERE Student_ID = 102;

-- Update with condition
UPDATE Students
SET Age = Age + 1
WHERE City = 'New York';

Example 4: DELETE Statement

Remove records from table.

-- Delete specific record
DELETE FROM Students
WHERE Student_ID = 101;

-- Delete with condition
DELETE FROM Students
WHERE Age < 18;

-- Delete all records (use carefully!)
DELETE FROM Students;

Example 5: WHERE Clause

Filter records based on conditions.

-- Comparison operators
SELECT * FROM Students WHERE Age = 20;
SELECT * FROM Students WHERE Age > 20;
SELECT * FROM Students WHERE Age >= 20;
SELECT * FROM Students WHERE Age < 25;
SELECT * FROM Students WHERE Age != 20;

-- Logical operators
SELECT * FROM Students 
WHERE Age > 20 AND City = 'New York';

SELECT * FROM Students 
WHERE City = 'London' OR City = 'Paris';

SELECT * FROM Students 
WHERE NOT City = 'Tokyo';

-- IN operator
SELECT * FROM Students 
WHERE City IN ('New York', 'London', 'Paris');

-- BETWEEN operator
SELECT * FROM Students 
WHERE Age BETWEEN 20 AND 25;

Example 6: ORDER BY Clause

Sort results.

-- Sort ascending (default)
SELECT * FROM Students
ORDER BY Age;

-- Sort descending
SELECT * FROM Students
ORDER BY Age DESC;

-- Sort by multiple columns
SELECT * FROM Students
ORDER BY City, Age DESC;

-- Sort with LIMIT
SELECT * FROM Students
ORDER BY Age DESC
LIMIT 5;  -- Top 5 oldest students

Example 7: Aggregate Functions

Perform calculations on data.

-- COUNT: Number of records
SELECT COUNT(*) FROM Students;
SELECT COUNT(*) FROM Students WHERE Age > 20;

-- SUM: Total of numeric column
SELECT SUM(Marks) FROM Grades;

-- AVG: Average value
SELECT AVG(Age) FROM Students;

-- MIN and MAX
SELECT MIN(Age) FROM Students;
SELECT MAX(Age) FROM Students;

-- Multiple aggregates
SELECT 
    COUNT(*) as Total_Students,
    AVG(Age) as Average_Age,
    MIN(Age) as Youngest,
    MAX(Age) as Oldest
FROM Students;

Example 8: GROUP BY Clause

Group rows with same values.

-- Count students by city
SELECT City, COUNT(*) as Student_Count
FROM Students
GROUP BY City;

-- Average age by city
SELECT City, AVG(Age) as Average_Age
FROM Students
GROUP BY City;

-- Multiple grouping
SELECT City, Gender, COUNT(*) as Count
FROM Students
GROUP BY City, Gender;

Example 9: HAVING Clause

Filter grouped results.

-- Cities with more than 5 students
SELECT City, COUNT(*) as Student_Count
FROM Students
GROUP BY City
HAVING COUNT(*) > 5;

-- Average age > 21
SELECT City, AVG(Age) as Avg_Age
FROM Students
GROUP BY City
HAVING AVG(Age) > 21;

-- Difference: WHERE vs HAVING
-- WHERE filters before grouping
-- HAVING filters after grouping

Hour 2: Advanced SQL & Transactions

JOIN Operations

JOIN combines rows from two or more tables based on related columns.

Example 10: INNER JOIN

Returns matching records from both tables.

-- Join Students and Enrollments
SELECT 
    Students.Name,
    Courses.Course_Name,
    Enrollments.Grade
FROM Students
INNER JOIN Enrollments 
    ON Students.Student_ID = Enrollments.Student_ID
INNER JOIN Courses 
    ON Enrollments.Course_ID = Courses.Course_ID;

-- Using table aliases
SELECT 
    s.Name,
    c.Course_Name,
    e.Grade
FROM Students s
INNER JOIN Enrollments e ON s.Student_ID = e.Student_ID
INNER JOIN Courses c ON e.Course_ID = c.Course_ID;

Example 11: LEFT JOIN

Returns all records from left table, matching from right.

-- All students, even without enrollments
SELECT 
    s.Name,
    c.Course_Name
FROM Students s
LEFT JOIN Enrollments e ON s.Student_ID = e.Student_ID
LEFT JOIN Courses c ON e.Course_ID = c.Course_ID;

-- Students not enrolled in any course
SELECT s.Name
FROM Students s
LEFT JOIN Enrollments e ON s.Student_ID = e.Student_ID
WHERE e.Student_ID IS NULL;

Example 12: Subqueries

Query within another query.

-- Students older than average age
SELECT Name, Age
FROM Students
WHERE Age > (SELECT AVG(Age) FROM Students);

-- Students enrolled in DSA
SELECT Name
FROM Students
WHERE Student_ID IN (
    SELECT Student_ID
    FROM Enrollments
    WHERE Course_ID = 'CS101'
);

-- Correlated subquery
SELECT Name, Age
FROM Students s1
WHERE Age > (
    SELECT AVG(Age)
    FROM Students s2
    WHERE s2.City = s1.City
);

JOIN Types Summary:

  • INNER JOIN: Only matching records
  • LEFT JOIN: All from left + matching from right
  • RIGHT JOIN: All from right + matching from left
  • FULL JOIN: All records from both tables

Transactions

A transaction is a sequence of operations performed as a single logical unit of work.

Real-World Example: Bank Transfer

Transaction: Transfer $100 from Account A to Account B

Step 1: Deduct $100 from Account A
Step 2: Add $100 to Account B

Both steps must succeed or both must fail!
If Step 1 succeeds but Step 2 fails:
- Money disappears (data inconsistency)
- Transaction ensures: All or Nothing

Example 13: Transaction Commands

-- Start transaction
BEGIN TRANSACTION;

-- Perform operations
UPDATE Accounts 
SET Balance = Balance - 100 
WHERE Account_ID = 'A001';

UPDATE Accounts 
SET Balance = Balance + 100 
WHERE Account_ID = 'A002';

-- If all successful, commit
COMMIT;

-- If error occurs, rollback
ROLLBACK;

Example 14: Transaction with Error Handling

BEGIN TRANSACTION;

-- Check if sufficient balance
IF (SELECT Balance FROM Accounts WHERE Account_ID = 'A001') >= 100
BEGIN
    -- Deduct from sender
    UPDATE Accounts 
    SET Balance = Balance - 100 
    WHERE Account_ID = 'A001';
    
    -- Add to receiver
    UPDATE Accounts 
    SET Balance = Balance + 100 
    WHERE Account_ID = 'A002';
    
    -- Success - commit
    COMMIT;
    PRINT 'Transfer successful';
END
ELSE
BEGIN
    -- Insufficient balance - rollback
    ROLLBACK;
    PRINT 'Insufficient balance';
END

ACID Properties

Transactions must follow ACID properties to ensure data integrity.

Atomicity

All or nothing. Transaction either completes fully or not at all.

Transfer money:
✓ Both debit and credit
✗ Only debit (rolled back)

Consistency

Database remains in valid state before and after transaction.

Total money before = 
Total money after

Constraints maintained

Isolation

Concurrent transactions don't interfere with each other.

Two transfers happen:
Each sees consistent data
No interference

Durability

Once committed, changes are permanent even if system crashes.

After COMMIT:
Data saved permanently
Survives power failure

Transaction Importance:

  • Data Integrity: Maintains consistency
  • Error Recovery: Can undo changes
  • Concurrent Access: Multiple users safely
  • Business Logic: Ensures rules followed
  • Reliability: Guarantees data safety

Real-World Transaction Examples:

  • Banking: Money transfers, withdrawals
  • E-commerce: Order placement, payment
  • Booking: Flight/hotel reservations
  • Inventory: Stock updates
  • Healthcare: Patient record updates

Key Takeaways

  • SQL is the standard database query language
  • SELECT retrieves data, INSERT adds data
  • UPDATE modifies data, DELETE removes data
  • WHERE filters records, ORDER BY sorts results
  • Aggregate functions: COUNT, SUM, AVG, MIN, MAX
  • GROUP BY groups data, HAVING filters groups
  • JOIN combines tables (INNER, LEFT, RIGHT, FULL)
  • Transactions ensure data consistency
  • COMMIT saves changes, ROLLBACK undoes them
  • ACID properties: Atomicity, Consistency, Isolation, Durability
